Delta Dashboard Architecture

Vue 3 · TypeScript · Vite · Pinia · Element Plus — layered frontend architecture for Delta Electronics prototype

純前端原型：以 Service 層 + 計時器模擬 REST / SSE 後端，數據由預生成腳本逐格播放

資料處理流程 — 無後端的模擬方式

  1. 1
    初始載入（模擬 REST）

    App 啟動時，experimentService 以 await delay(1000ms) 模擬網路延遲，回傳 mock 資料給各 store。元件全程不直接碰 mock，未來接上真實後端時只需替換 service 層實作。

  2. 2
    腳本預先生成（取代後端運算）

    monitorStore 初始化時，scriptGenerator 依模擬設定，為每個物件預生成 20 格數據（基礎值 + 漂移量 + 隨機雜訊）。因加入隨機性，每次執行的數值與告警時點都會有差異。

  3. 3
    模擬即時串流（模擬 SSE）

    setInterval(500ms) 模擬伺服器推播，共 20 個 tick （約 10 秒）。每個 tick 只推 tick 編號，數值由前端依腳本播放，不索取也不傳輸真實數據。

  4. 4
    每個 tick 的資料處理

    單例 useExperimentStream 收到事件後，依序更新：指標 → KPI → 告警（去重）→ 日誌 → 物件狀態 → 進度。最後一個 tick 做 onComplete，實驗自動完成。

  5. 5
    操作與版本切換（樂觀更新）

    所有操作（stop / rerun / 版本切換）都先更新顯示狀態，即時響應 UI，再以 fire & forget 呼應模擬 API。版本切換前會保存狀態以供 revert 還原；rerun 則重生腳本並重置版本。

UI Layer

  • • 3 component groups: App Shell, Dashboard Views, Detail Panel
  • • SparklineChart.vue — vue-chartjs + chart.js, warning/critical dashed lines
  • • ChangeVersionDialog — version swap flow with revert
  • • Components never import mock data directly
  • • Element Plus for UI primitives and notifications

State & Orchestration

  • • useExperimentStream — singleton module-level sub
  • • useExperimentSession — cross-store derived state & actions
  • • 4 Pinia stores: experiment / object / monitor / version
  • • Optimistic updates — all mutations fire & forget
  • • Status watcher auto-starts/stops stream on re-run
  • • Version swap saves pre-swap state; rerun promotes current → last run

Simulation Engine

  • • subscribeToExperimentStream — setInterval(500ms)
  • • 20 ticks total ≈ 10s experiment run time
  • • Each tick: metrics → KPIs → alerts → logs → objects → progress
  • • Scripts generated per run: baseValue + drift + noise — alert timing is probabilistic
  • • Alerts deduped per object + metric + severity
  • • REST stubs: await delay(300–1000ms) per call
