# 設計反思：實驗監控 Dashboard

從這份作業延伸出來的產業認識、技術背景、以及對監控場景 UIUX 的思考框架。

---

## 產業背景

**SCADA / HMI 是什麼**
HMI 是操作員與機器互動的介面（工廠觸控螢幕）；SCADA 是更上層的跨廠區監控系統。傳統做法是用專屬軟體（Ignition、TIA Portal、Delta 自家的 DIAView）拖拉元件，不涉及 web 開發。

**Web 化趨勢**
工業介面正在往 web 技術靠攏。監控場景用 WebSocket + 時序資料庫（InfluxDB）+ Vue/React 已經足夠；需要即時控制時，web 只負責「人下指令」這層，真正的毫秒級控制永遠在 PLC，不會被 web 取代。

**數位孿生**
- Level 1：視覺化監控，3D 模型 + 即時數據疊加
- Level 2：模擬預測，在數位空間先驗證參數調整效果，再下指令給真實設備
- Level 3：自主優化，孿生持續學習，自動調整實體設備（研究階段）

Level 1 的核心價值不是視覺效果，而是把符號式佈局換成空間對應佈局，降低大型場景的空間認知負荷。點擊 3D 模型裡的機台等於點擊真實空間裡的那台機器，操作員不需要學習符號系統。很多「數位孿生」產品只是把數字貼在 3D 模型上，沒有改變資訊架構，沒有實質差異。

## 監控場景的 UIUX 設計框架

**降低認知負荷**
操作員要能快速理解當前狀態。ISA-101 規範的核心原則：正常狀態用低飽和度，顏色只用來表達異常；動畫只用於反映真實物理動作，不做裝飾。

**縮短決策時間**
從察覺異常到採取行動之間的摩擦越少越好。告警要在第一時間說清楚「什麼東西、發生什麼、嚴重程度」，相關資訊要在同一個視線範圍內。

**防止操作錯誤**
高風險操作的代價可能是人命或巨額損失。設計要讓正確操作比錯誤操作更自然，不可逆操作需要明確提示。ISA-101 存在的根本原因之一就是糟糕的 HMI 介面曾造成工安事故。

**人在自動化中的定位**
自動化程度越高，設計問題就從「如何讓人快速操作」轉變成「如何讓人知道何時該介入」。長期不操作的操作員會失去情境感知（situation awareness），遇到突發狀況反應更慢，這叫 automation complacency。航空業研究這個問題幾十年了，工業自動化正面對同樣的問題。

---

## 這次專案的反思

這次設計主要在場景定位、資訊架構、操作流程三個層次，沒有深入防錯設計和自動化中的人的角色。

這個框架是做完之後才整理出來的，記錄在這裡是為了提醒自己做設計時保持這個宏觀視角，最後仍能收斂成直覺的設計成果。
